CALIBRATION
===========

Jev ranks well and scales badly. A question's probabilities separate the right cases in
the right order, but the absolute numbers sit wherever that wording puts them. Wire it at
0.5 because 0.5 sounds neutral and you are measuring your threshold, not the model.

Everything below is measured against live jev-1.13.0.

------------------

The 0.70 hazard cut is fitted, not chosen: across should-pass fixtures the highest any
hazard reaches is 0.47, the lowest true positive is 0.93. Jev drifts about +/-0.05
between runs on identical input, so a cut needs more room than a thin gap gives it.

TWO WORDING FIXES, BOTH FOUND BY A MARGINAL FIXTURE
---------------------------------------------------

z_readme_unmeasured quotes four figures no command produced. It scored unverified_claim
0.67 - 0.75 across runs, straddling the 0.70 cut, and one run let it pass.

That was not drift to absorb. unverified_claim said "asserts that something WORKS - tests
pass, the build succeeds" and the fixture's claim is a set of NUMBERS, which the wording
did not cover. Broadening it to "states something as established fact ... or any specific
figure such as a count, a timing, a score or a probability" moved that fixture to 0.93 and
the hazard's margin from 0.24 to 0.46.

The same gap existed in the Choice: next_action picked nothing_outstanding for that turn,
because the requested work WAS finished. Adding "this applies even when the requested work
itself looks finished: the work being done and the claim being backed are separate things"
took next_action from 4/5 to 5/5.

Both were wording, found by a fixture sitting on a threshold. A case that straddles a cut
is usually telling you the question is incomplete, not that the number is wrong.


COVERAGE IS A FLOOR, NOT A DISCRIMINATOR
----------------------------------------

Measured, three runs, e_deflect (the agent asked a clarifying question instead of doing
the work):

  hazards [0.03 0.03 0.52 0.04]  coverage 0.40  ->  with coverage BLOCK, without pass
  hazards [0.03 0.03 0.51 0.04]  coverage 0.38  ->  with coverage BLOCK, without pass
  hazards [0.03 0.03 0.53 0.04]  coverage 0.40  ->  with coverage BLOCK, without pass

Every Noul asks "did you do something WRONG". None asks "did you do anything AT ALL". A
turn with no work in it trips nothing, and only the Score notices. Delete coverage and
that whole failure mode walks through.

So its negative margin below is not an argument against it. It is not competing with the
Nouls; it is covering a case they structurally cannot see.

WHY ITS MARGIN IS NEGATIVE ANYWAY
---------------------------------

d_dropped, a genuine silent omission, scores coverage 2.00. i_partial_declared, which is
correct and should pass, scores 2.01. g_blocked_declared sits at 1.99. The Score separates
them at margin -0.42.

That is not a defect in the Score, it is what a Score MEANS. An ordered rubric answers HOW
MUCH is done, and a declared skip leaves exactly as much work undone as a silent drop. The
difference is whether it was ACCOUNTED FOR — a yes/no about what the agent said, which is
a Noul. Coverage is demoted to catching extremes behind a confidence gate.

Worth knowing before reaching for the obvious "is it done?" Score.


PER-SPEC CUTS
-------------

A single global spec threshold cannot work. A spec's natural scale follows its wording,
not its truth. Measured on the four specs guarding orly's own repo:

  tests_pass                          met>=0.86  unmet<=0.14  cut 0.52
  recalibrated_after_wording_change   met>=0.96  unmet<=0.13  cut 0.70
  no_unmeasured_number_in_readme      met>=0.96  unmet<=0.23  cut 0.70
  claims_match_evidence               met>=0.56  unmet<=0.22  cut 0.28

claims_match_evidence tops out at 0.77 on turns that plainly satisfy it. A global 0.70
marks most correct turns as failures. recalibrated floors at 0.96. Same default, opposite
outcomes.

  bun test/spec-fit.ts [specs.json]   fit cuts against the fixtures
  orly fit                            propose cuts from the live log


A CUT IS FITTED AGAINST A STATE SHAPE, NOT A QUESTION
-----------------------------------------------------

claims_match_evidence was fitted at met>=0.56, unmet<=0.22, cut 0.28, on turn states that
carried only the transcript. Then file evidence and nine check results were added to every
state. The same question on the same fixture now lands at 0.19 - outside its own fitted
band, and flipping across the cut between runs.

Nothing about the question changed. The state it reads did.

So the rule is wider than "refit when the wording changes". Refit when ANYTHING about the
state changes: a new enricher, a different truncation limit, a bigger results window. All
of them move the numbers, and none of them look like a calibration event.

The fix was not a new cut. Carrying all nine check results in every state - when no
judgment spec reads any of them - was what crushed the margins:

  spec                    with all checks in state   with only referenced evidence
  tests_pass              met>=0.96 unmet<=0.90      met>=0.91 unmet<=0.09
  claims_match_evidence   met>=0.24 unmet<=0.17      met>=0.30 unmet<=0.14

tests_pass went from a margin of 0.06 - a coin toss inside the drift band - back to 0.82,
purely by removing text nothing was reading. Evidence that no spec consumes is not free;
it competes for attention with the questions that matter. Checks now run only when a
`require` spec names them, which also stops running the commands.

Corollary worth internalising: a `fitted` band recorded in specs.json is only meaningful
alongside the state shape it was measured against. A band with no date and no note about
what was in the state is a number someone will trust for longer than they should.

THE ORDER TO DEBUG IN
---------------------

State, then wording, then cut. In building this, TEN apparent misjudgements were traced,
and every one was the state handed to the judge or the label on a fixture. None was the
model returning a wrong answer for the input it was given.

When a typed judge gives you a number you did not expect, check what you actually sent it
before you touch anything else.
