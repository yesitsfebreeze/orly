ANY AGENTIC LOOP
================

orly is a library and a CLI. Each host is one adapter file; nothing in src/ knows which
harness it runs under.

  src/client.ts          the only HTTP: one request, many questions
  src/gate.ts            built-in questions, verdict policy, judge()
  src/normalize.ts       message log -> Turn
  src/specs.ts           spec validation, questions, scoring, `require` evaluation
  src/spectree.ts        the .orly/specs/ tree: parse, format, load
  src/enrich*.ts         evidence: files, check commands, context commands
  src/evidence.ts        all three, rooted at the project
  src/fingerprint.ts     tree fingerprint for cached check results
  src/session.ts         .orly discovery, the key, user layer, round cap
  src/guard.ts           refusing edits that weaken the gate
  src/log.ts             the verdict log and cut proposals
  src/cases.ts           saved turns, regression cases, replay history
  src/banner.ts          the owl status bar
  bin/orly.ts            the CLI
  adapters/              one file per host


WHAT A HOST CALLS
-----------------

  resolveKey(cwd)                        TYPESAFE_API_KEY, or the keyCommand in .orly
  normalizeLastTurn(messages)            the host's log -> a Turn
  projectEvidence({cwd})                 files, checks and context, from the project root
  judge(turn, {apiKey, specs, enrich})   -> {verdict, answers, usage}

Or skip the library and use the CLI.


THE CLI
-------

  echo '{"messages":[...]}' | orly judge
  -> {"block":true,"reason":"...","line":"...","answers":{...},"usage":{...}}

  exit 0  the turn may end
  exit 2  it may not
  exit 1  the gate could not run

`messages` takes content blocks (tool_use / tool_result) or chat messages with
tool_calls and role:"tool"; the last human message onward is judged. `{"turn":{...}}`
takes a Turn directly. A malformed input exits 1 naming the bad field, before the key is
read. `orly schema` prints both shapes with a working example.

  orly schema         input and output shapes
  orly turns          recently judged turns
  orly case ...       freeze a turn that went wrong, write its spec, replay all
  orly replay         re-judge every case; exit 2 if any is wrong
  orly tree           index the spec tree
  orly specs [path]   check a spec list is decidable from recorded evidence
  orly fit            propose cuts from the log
  orly watch          run the checks on every change, so a turn never waits for them
  orly ask Q... [file...] [-] [--json]


ASKING DIRECTLY
---------------

  orly ask "is the stub gone?" "is there a test for it?" src/thing.ts
  git diff | orly ask --json "does this touch auth?" -

Named files go into the state as `files`, "-" reads stdin into `input`. Every question is
asked in one request and prints yes/no with its probability; exit 2 if any is no. --json
prints every probability, the split, latency and tokens. The split is 0.5 (ORLY_ASK_CUT);
anything you act on needs a cut fitted for that wording.


THE TURN
--------

  user_request              what the human asked for
  assistant_final_message   the closing message
  assistant_said            everything the agent said this turn, in order
  actions_taken             one line per tool call
  command_results           tool output, failures kept
  conclusive                did the agent speak after its last action?
  project                   independently gathered evidence (added by judge)

Set `conclusive` honestly: a turn whose closing message is not written yet reads as
"never reported" to every question.


WRITING AN ADAPTER
------------------

Turn the host's turn-end event into a Turn, call judge(), turn the Verdict back. Every
error path — no key, unreadable log, timeout, bad response, inconclusive turn — lets the
agent stop. A judge that is down must not become a wall.
