GETTING BETTER INSTEAD OF STAYING STILL
=======================================

Nothing learns by itself. A gate improves because someone writes the improvement down.
These are the mechanisms that make that cheap and make it spread.


HOT RELOAD
----------

The plugin source is a directory link and the hook spawns a fresh process every turn.
Edit the code or the specs and the next judgment uses them — no restart, no reinstall.


THE LOG
-------

Every judgment appends one line to .orly/log.jsonl: timestamp, session, blocked, every
question's probability, which specs went unmet, which hazards fired, and counts of actions
and results. No transcript — counts are enough to tell a thin turn from a long one.

Cuts fitted on twelve hand-written fixtures are fitted on one person's idea of what going
wrong looks like. Cuts fitted on a thousand logged turns are fitted on what actually
happens.


THE LABELS ARE FREE
-------------------

  worked     the block was followed by real work — it bought something
  explained  the block was followed by talk alone, then a pass — it probably cost a round

Weak labels, deliberately. Evidence to look at, not facts. Unlabelled is neither: a block
only earns a label once the same session judges another turn after it.

  orly fit    propose cuts from the log

It prints and applies nothing. Tightening is yours to apply; loosening should be confirmed
by a human, because an agent that lowers its own bar will lower it until nothing fires.
When the two populations overlap it proposes nothing at all — overlap means the WORDING is
wrong, not the threshold.


THE SESSION BANNER
------------------

SessionStart injects the current spec set, the cuts, which are unfitted, what fires and
what it bought, and the rules for tuning. Without it a fresh session has no idea that
editing the spec set is in scope, so the gate stays exactly as good as the day it was
written, forever.


ONE LESSON, EVERY PROJECT
-------------------------

  ~/.orly/cuts.json   spec id -> cut, inherited by any project spec that states none
  ~/.orly/specs.json  specs that apply everywhere

Fit a wording once and every repo gets it. The project always overrides.
